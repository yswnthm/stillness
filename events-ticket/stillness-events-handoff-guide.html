Overview

What has been set up

The Events system has been built using WooCommerce products. Each event is created as a WooCommerce product under the Events category.

Events Page

Shows upcoming or past events using the event product details, image, price, date, duration, and venue.

Single Event Page

Shows the full booking page for one event with image, description, ticket quantity, and booking button.

Waitlist Form

One shared Events waitlist form is used on both the Events page and individual event pages.

Booking Flow

Paid event bookings are handled by normal WooCommerce checkout and appear inside WooCommerce Orders.

Important: Do not edit the page layout directly unless needed. For normal event updates, only update the WooCommerce product content, stock, price, and image.

Booking Flow

What happens after someone books

When someone purchases an event ticket, WooCommerce handles it like a normal product order.

Person What they receive or see
Customer Receives the normal WooCommerce order confirmation email with their order and product details.
Admin team Can see the booking inside WooCommerce → Orders, including customer name, email, event product, ticket quantity, payment status, and order status.

Email decision: No custom WooCommerce email design is required for now. The default WooCommerce email is enough because the current requirement is to collect the buyer name and email so the team can contact them.

If one person books multiple tickets, WooCommerce will show the purchased quantity. It will not collect separate names for each attendee unless a custom attendee form is added later.

Event Products

Add a new event

  1. Go to Products inside WordPress.
  2. Duplicate a previous event product, or click Add New.
  3. Enter the event title.
  4. Set the product type to Simple product.
  5. Check Virtual.
  6. Leave Downloadable unchecked.
  7. Add the ticket price.
  8. Open Inventory and enable stock management.
  9. Set stock quantity to the number of available seats.
  10. Set backorders to Do not allow.
  11. Upload the main event image as the product image.
  12. Assign the product category Events.
  13. Add the short description.
  14. Add the long description.
  15. Add the required event attributes.
  16. Publish the product only after all details are ready.

Catalog Order

Change the order of events on the Events page

The order of the event cards is controlled by each event product's published date and time.

Simple rule: the event with the newest published date/time appears first.

Page area How the order is chosen
Featured event panel Shows the newest published event that still has stock available.
Three event cards below Shows the three newest published event products from the Events category.
Sold-out event cards Sold-out events can still appear in the three cards, but they will automatically show the sold-out state.

Steps to swap the order

  1. Go to Products inside WordPress.
  2. Open the event product that should move.
  3. In the right sidebar, find the Publish box.
  4. Look for the line that says something like Published on: Jun 15, 2026 at 10:30.
  5. Click Edit beside that Published on line.
  6. Set a newer date/time if the event should move earlier on the Events page.
  7. Set an older date/time if the event should move later on the Events page.
  8. Click OK.
  9. Click Update.
  10. Refresh the Events page and check the order.

Example: If the third event card should become the first card, open that event product, adjust its published time so it is newer than the other events, click OK, then click Update.

Use small time changes when possible, such as changing only the minutes. This keeps the product history tidy while still changing the visible catalog order.

If the featured event changes unexpectedly, check which in-stock event has the newest published date/time. The featured panel always follows the newest in-stock event.

Content Rules

Event content rules

Required attributes

Every event must include these three custom attributes. Use the exact names.

Attribute name Example value Where it appears
Event Dates 15 June 2026 Event cards and single event details
Duration 2 Hours Event cards and single event details
Sanctuary The Stillness Studio, Toronto Event cards and single event details

FAQ Attributes (Optional)

If you want to display an FAQ section for a specific event, add matching Question and Answer attributes. You can add up to 30 pairs.

Attribute name Example value Where it appears
Q1, Q2, etc. What should I pack? FAQ section (Question title)
A1, A2, etc. Comfortable, breathable clothing... FAQ section (Answer text)

Note: Both the question (e.g. Q1) and the answer (e.g. A1) must be present for the FAQ item to appear. If no Q/A attributes are found, the FAQ section will be hidden entirely.

Short description

Use the short description for a calm 1-2 line teaser. Do not add date, duration, location, or emoji-style logistics here.

Example: Step into the new season with clarity, energy, and renewed purpose.

A gentle immersion of movement, meditation, and guided reflection designed to release the weight of winter.

Long description

Use the long description for the full event story, sections, and details. This appears on the individual event page.

Availability

Stock, ticket quantity, and sold-out state

Ticket quantity

Visitors can choose more than one ticket before checkout. The selected quantity is limited by the available WooCommerce stock.

Mark an event sold out

  1. Open the event product.
  2. Go to Product Data → Inventory.
  3. Set stock quantity to 0.
  4. Click Update.

The event page will automatically show the sold-out state and guide people toward the waitlist.

Increase capacity

  1. Open the event product.
  2. Go to Product Data → Inventory.
  3. Increase the stock quantity.
  4. Click Update.

Waitlist

Waitlist form

The Events waitlist form is separate from paid WooCommerce bookings. It is used when someone wants updates or when an event is sold out.

Area Details

Shortcode [metform form_id="6697"]
Used on Events catalog page and individual event pages

To check waitlist submissions, go to MetForm and open the Entries or Submissions area for the Events form.

Orders

Check bookings and guest details

  1. Go to WooCommerce → Orders.
  2. Search by customer name, email, or event product name.
  3. Open the paid order.
  4. Check the customer name and email.
  5. Check the event product name and purchased quantity.
  6. Use only paid or processing orders for confirmed attendance.

Current workflow: For event bookings, the team only needs buyer name and email. If they later need every attendee name for multi-ticket orders, that should be added as a separate custom booking requirement.

No Upcoming Event

When no event is open

Do not create a fake placeholder product.

If no event product has stock available, the website automatically shows a New Retreat Dates Coming Soon state and keeps the waitlist available.

Past events can remain published if they should appear in the Events grid. Make sure past events are not bookable by setting stock to 0.

Before Publishing

Final checklist for each event

  • Product title is correct.
  • Product type is Simple product.
  • Virtual is checked.
  • Downloadable is unchecked.
  • Price is correct.
  • Stock quantity matches available seats.
  • Backorders are disabled.
  • Product image is uploaded.
  • Category is set to Events.
  • Short description is clean and does not include logistics.
  • Long description contains the full event story.
  • Attributes are exactly named Event Dates, Duration, and Sanctuary.
  • Test the event page on mobile.
  • Test one booking before publicly announcing the event.
